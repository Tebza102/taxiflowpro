# Frontend Design Skill

## Purpose
Use this skill for distinctive production-grade frontend interface direction and implementation planning across:
- landing pages
- websites
- web app interfaces
- dashboard concepts
- scroll-driven pages
- cinematic hero sections
- interactive product pages
- mobile-first frontend experiences
- reference-led frontend redesigns
- non-generic UI systems

This skill exists to prevent generic AI frontend output and force brief-led, business-aware, reference-aware design decisions.

## No Generic AI Aesthetic Rule (Mandatory)
Do not default to:
- endless cards
- creamy white SaaS layouts
- repetitive rounded panels
- generic icon rows
- random gradients
- predictable boxed hero sections
- glassmorphism cards by default

Design must be specific to the brief, audience, and brand.

## Required Frontend Design Workflow
1. Brief interpretation
2. Target user and business purpose
3. Aesthetic direction selection
4. Reference analysis if provided
5. Typography strategy
6. Color and theme strategy
7. Motion strategy
8. Spatial composition strategy
9. Layout variety plan
10. Component strategy
11. Mobile behavior
12. Accessibility and performance considerations
13. Anti-generic design check
14. Files likely to change
15. Test plan

## Card Budget Rule
Public websites and landing pages:
- should not be card-heavy unless the brief requires it
- text does not need to sit inside boxes
- hierarchy can come from type, space, contrast, alignment, imagery, and motion

Dashboards and data interfaces:
- cards are acceptable for KPIs and grouped metrics
- still enforce visual discipline and avoid panel clutter

## Scroll-Driven Page Rules
For scroll-driven websites and long landing pages:
- typography can replace containers
- layout patterns must vary by section
- section rhythm matters
- motion must be choreographed, not random
- oversized type, pinned sections, color zones, and horizontal movement can be used where appropriate
- do not use glassmorphism cards as a default pattern

For scroll-driven video/canvas websites, use `video-to-website-skill.md` as the primary implementation skill.

## Reference-Led Extraction (When Provided)
Extract before designing:
1. layout structure
2. spacing rhythm
3. typography mood
4. color behavior
5. image treatment
6. motion language
7. hierarchy strategy
8. emotional tone
9. what makes it distinctive
10. what must not be copied directly
11. what should be adapted

## Accessibility and Performance Guardrails
- maintain readable contrast and type sizes
- preserve keyboard/focus clarity where UI is interactive
- avoid heavy visuals that damage page performance
- keep animation meaningful and lightweight
- keep mobile readability and tap targets practical

## Required Output
For planning:
- brief interpretation
- user/business intent
- aesthetic direction
- reference analysis
- type/color/motion strategy
- layout and component strategy
- mobile and accessibility notes
- file impact and test plan

For implementation:
- files changed
- what changed visually
- how the design avoids generic patterns
- card budget outcome
- responsive checks
- remaining risks

## Stop Conditions
Stop and ask for clarification if:
- brand direction is unclear
- references conflict with the brief
- required assets are missing
- the requested style would harm usability or readability
