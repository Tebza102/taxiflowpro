## 2. Policies, functions, triggers, keys and defaults
- **Policies:** only on `workspace_snapshots`, all PERMISSIVE for `authenticated`:
  - "Authenticated users can read workspace snapshots" (SELECT, `using true`);
  - "… can insert …" (INSERT, `with check true`);
  - "… can update …" (UPDATE, `using true`, `with check true`).
- **Functions in `public`:** none. **Triggers in `public`:** none. The held `20260810_protect_workspace_appusers` was never applied, and it is superseded.
- **Foreign keys:**
  - `workspace_snapshots.updated_by → auth.users`;
  - the legacy tables reference `personnel_profiles`, `vehicles` and `banking_events` among themselves (10 FKs).
- **Unique keys:** `vehicles.registration` and `banking_events.reference_code`. **Checks:** `personnel_profiles.role`, `compliance_documents.subject_type`.
- **Columns:** match `supabase/schema.sql`, except that `shift_reconciliations` has **no** columns from `20260405_add_trip_analytics_fields.sql`. That migration was never applied and is not needed.
- **Migration history:** there is no `supabase_migrations.schema_migrations` table. Schema changes were applied by hand.
- **Default privileges in `public`:** both `postgres` and `supabase_admin` grant `anon`, `authenticated` and `service_role` ALL on new tables, sequences and functions. Any new object is browser-accessible unless revoked explicitly.
- **Schema `public`:** USAGE for anon and authenticated. `taxiflow_private` and `taxiflow_local` do not exist.
- **Extensions:** pgcrypto 1.3, uuid-ossp 1.1, supabase_vault 0.3.1.

**What 01 does on the hosted project:**
- drops all policies on `workspace_snapshots` (found dynamically);
- revokes all anon, authenticated and PUBLIC privileges on every `public` relation, including the view;
- enables RLS on every `public` table;
- makes the view `security_invoker`;
- revokes all anon, authenticated and PUBLIC execute on `public` functions;
- revokes the `postgres` default privileges;
- creates the tenant tables, mapping, backfill and helpers;

- runs assertions (no policy left, exact browser grants, RLS everywhere, no browser-executable function, the legacy business has an active Owner). Any failure rolls back the whole file.

**Not covered:** `supabase_admin` default privileges cannot be changed by `postgres`. TaxiFlow never creates objects as `supabase_admin`, and every migration revokes explicitly. The rehearsal asserts the result.
